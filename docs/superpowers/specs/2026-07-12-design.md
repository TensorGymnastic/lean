# Lean MCP Pipeline — Design Spec

- **Date:** 2026-07-12
- **Status:** Draft (awaiting user approval)
- **Work ID:** `lean-mcp-pipeline`
- **Target repo:** `repos/quanti/lean/` (new)
- **Author:** Sisyphus (OhMyOpenCode), with user

## 1. Overview

Build `lean`, a Python service that ingests Lean Six Sigma PDFs into a queryable
corpus and exposes the corpus to AI agents over the Model Context Protocol (MCP).

The pipeline: PDF → markdown (Unlimited-OCR primary, markitdown fallback) →
section-aware chunks → Liquid LMF embeddings → Supabase pgvector. The surface
is a `fastmcp` v3.x server exposing 8 tools, 4 resources, and 3 prompts, plus
an optional FastAPI mirror for non-agent HTTP clients.

The seed corpus is 4 commercially-published Lean Six Sigma books already present
in `repos/quanti/lean/`. The code is corpus-agnostic — any PDF path works.

## 2. Goals & success criteria

**Goals:**
1. Ingest the 4 seed PDFs end-to-end into Supabase pgvector via MCP tool call.
2. Answer Lean Six Sigma questions via MCP `search` tool with section-path citations.
3. Run entirely on the host (RTX 2000 Ada 8GB, CUDA 12.6) with no cloud spend.
4. Be consumable by Claude Desktop, opencode, and any MCP client over stdio or HTTP.

**Success criteria (verifiable):**
- `make ingest-all` ingests all 4 PDFs with zero unhandled errors.
- `corpus_stats` MCP tool returns ≥4 documents and >0 chunks per document.
- For 5 canonical Lean Six Sigma queries (DMAIC, kaizen, takt time, voice of
  the customer, control chart), `search` returns ≥3 relevant chunks with correct
  section paths.
- `mcp-serve` starts in <5 seconds (excluding vLLM warmup).
- vLLM sidecar healthcheck passes within 90 seconds of `make vllm-up`.
- `make verify` (ruff + mypy + pytest) passes clean.

```
                                                  │ HTTP (page images + prompts)
                                                  │ via network or SSH tunnel
                                                  ▼
┌──────────────────────────────────────────────────────────────────────┐
│  Remote GPU host (3080 Ti, 12GB VRAM, SSH-reachable)                   │
│                                                                        │
│  ┌────────────────────────────────────────────────────────────────┐  │
│  │ vLLM server: baidu/Unlimited-OCR (3B BF16, ~6GB VRAM)          │  │
│  │ OpenAI-compatible HTTP API on :8000                             │  │
│  │ Started via: `vllm serve baidu/Unlimited-OCR --host 0.0.0.0`   │  │
│  │ OR via systemd service (documented in scripts/setup-3080ti.md) │  │
│  └────────────────────────────────────────────────────────────────┘  │
│                                                                        │
│  Driver/CUDA: controlled by us — install whatever vLLM image needs.   │
└──────────────────────────────────────────────────────────────────────┘

MCP clients (Claude Desktop, opencode, custom agents) ──stdio or HTTP/bearer──► lean-app
```

**Two local services + one remote service:**

1. **`supabase-db`** (local docker) — official Supabase CLI (`supabase start`) brings up
   Postgres 15 + pgvector, Auth, Storage, Realtime. Local-only. Data persists
   in named docker volumes. Port 54322 (DB), 8000 (Supabase Studio on host).
2. **`lean-app`** (local docker) — built from repo `Dockerfile`. Runs the `lean`
   Python package as a container. MCP HTTP on host port 8765 with bearer auth.
   Optional FastAPI mirror on host port 8766. stdio transport available when
   run via `docker run -i`. HF token mounted from `.env` (gitignored).
3. **`vllm-unlimited`** (remote 3080 Ti) — runs on the remote GPU host,
   started via `vllm serve baidu/Unlimited-OCR --host 0.0.0.0 --port 8000`
   (documented as a one-time setup; can be systemd-managed). Reachable from
   lean-app via direct network address OR SSH tunnel (configurable via
   `VLLM_BASE_URL` env var).

**VRAM budget on 3080 Ti (12 GB):**
- vLLM Unlimited-OCR: ~6 GB persistent
- Comfortable margin; LFM2.5-Embedding-350M stays on the lean-app host
  (CPU is fine — it's only 350M params, ~700 MB BF16, runs in seconds
  even on CPU).

**Network reachability options for vLLM (pick via `VLLM_BASE_URL`):**
- Direct: `http://3080ti-hostname:8000` (if the GPU host is on your LAN)
- SSH tunnel: `ssh -L 8000:localhost:8000 user@3080ti` → use `http://localhost:8000`
- Tailscale/Wireguard: `http://3080ti-tailScale-ip:8000`

The lean-app talks to vLLM via a single configurable base URL. No coupling
to a specific transport.

## 4. Components

Each module has one purpose, a clear interface, and is independently testable.

| Module | Purpose | Key deps |
|---|---|---|
| `lean.settings` | Pydantic-settings: Supabase URL/key, HF token, vLLM URL, chunk size | pydantic-settings |
| `lean.models.schemas` | Pydantic types shared across modules (Document, Chunk, IngestResult, etc.) | pydantic |
| `lean.extraction.unlimited_ocr` | vLLM HTTP client. Calls `infer_multi` style endpoint. Raises `OCRBackendUnavailable` on connection failure. | httpx |
| `lean.extraction.markitdown_fallback` | In-process markitdown PDF→MD. Used when vLLM is down or returns errors. | markitdown |
| `lean.extraction.pipeline` | Orchestrates: try Unlimited-OCR → fallback markitdown. Records `extraction_method` on Document. | both above |
| `lean.chunker.markdown_ast` | Parses markdown into AST (mistune). Walks headers (H1-H4) to build section paths. | mistune |
| `lean.chunker.recursive` | Recursive splitter. Target 350-450 tokens, hard cap 500. Splits on paragraph → sentence → token boundaries. Uses `tiktoken cl100k_base` for token counting — an approximation of LFM2.5's own tokenizer (which has a 65,536 vocab). The 12-50% safety margin under LFM's 512-token hard limit covers the mismatch in practice. | tiktoken |
| `lean.embeddings.liquid_lmf` | sentence-transformers wrapper. `prompt_name="query"` for queries, `"document"` for passages. Returns normalized 1024-dim. | sentence-transformers, torch |
| `lean.store.supabase` | Supabase client (DB + Storage). Uploads source PDF + extracted markdown to `sources` and `markdown` buckets. | supabase-py |
| `lean.store.pgvector` | Schema migrations, chunk insert with embedding, cosine search via `<=>` operator. | psycopg, pgvector |
| `lean.retrieval.search` | `search(query, k, doc_id?, section?)` → embeds query → pgvector top-k → returns Chunk list with scores. | embeddings + pgvector |
| `lean.mcp_server.tools` | 8 `@mcp.tool` definitions (see §6) | fastmcp |
| `lean.mcp_server.resources` | 4 `@mcp.resource` definitions (see §6) | fastmcp |
| `lean.mcp_server.prompts` | 3 `@mcp.prompt` definitions (see §6) | fastmcp |
| `lean.mcp_server.__main__` | Entry point. Parses `--transport {stdio,http}` flag. Default: stdio. | fastmcp |
| `lean.cli` | Typer CLI: `ingest`, `search`, `mcp-serve`, `db-init`, `reingest-all`. | typer |
| `lean.api.routes` | Thin FastAPI mirror of MCP tools (same handlers, REST shape) for non-agent HTTP clients (dashboards, curl). Included in v1 with no separate auth — same bearer-token auth as MCP HTTP. | fastapi |
| `lean.auth.bearer` | Static bearer token middleware for HTTP transport. Validates `Authorization: Bearer <LEAN_MCP_API_KEY>` against env var. stdio transport bypasses auth (local trusted). Returns 401 on missing/invalid token. | fastmcp, starlette |

## 5. Data model (Supabase / Postgres + pgvector)

```sql
-- db/schemas/001_extensions.sql
create extension if not exists vector;
create extension if not exists "uuid-ossp";
create extension if not exists pg_trgm;  -- section_path substring match

-- db/schemas/002_documents.sql
create table if not exists public.documents (
  id                  uuid primary key default uuid_generate_v4(),
  source_path         text not null,
  source_sha256       text not null unique,
  title               text,
  authors             text[],
  publisher           text,
  year                int,
  page_count          int,
  extraction_method   text not null
      check (extraction_method in ('unlimited_ocr', 'markitdown')),
  source_storage_path   text not null,    -- Supabase Storage object key for original PDF
  markdown_storage_path text not null,    -- Supabase Storage object key for extracted markdown
  ingested_at         timestamptz not null default now(),
  reingested_at       timestamptz,
  metadata            jsonb not null default '{}'::jsonb
);

-- db/schemas/003_chunks.sql
create table if not exists public.chunks (
  id            uuid primary key default uuid_generate_v4(),
  document_id   uuid not null references public.documents(id) on delete cascade,
  chunk_index   int  not null,
  section_path  text not null,
  heading_text  text,
  page_start    int,
  page_end      int,
  token_count   int  not null,
  content       text not null,
  embedding     vector(1024) not null,
  unique (document_id, chunk_index)
);

create index if not exists chunks_embedding_idx
  on public.chunks using ivfflat (embedding vector_cosine_ops) with (lists = 100);
create index if not exists chunks_document_id_idx on public.chunks (document_id);
create index if not exists chunks_section_path_idx
  on public.chunks using gin (section_path gin_trgm_ops);
```

**Storage buckets** (created via `supabase/seed.sql`):
- `sources` — original PDF files
- `markdown` — extracted markdown files

**Deduplication:** `source_sha256` is unique. Re-ingesting the same PDF
upserts the document and replaces its chunks atomically (transaction).

## 6. MCP surface (primary agent interface)

### Tools (8)

```python
@mcp.tool
def ingest_pdf(path: str) -> IngestResult: ...

@mcp.tool
def search(
    query: str,
    k: int = 5,
    doc_id: str | None = None,
    section: str | None = None,  # case-insensitive substring match on section_path
) -> list[Chunk]: ...

@mcp.tool
def get_chunk(chunk_id: str) -> Chunk: ...

@mcp.tool
def list_documents() -> list[DocumentSummary]: ...

@mcp.tool
def get_document_markdown(doc_id: str) -> str: ...

@mcp.tool
def delete_document(doc_id: str) -> bool: ...

@mcp.tool
def reingest(doc_id: str) -> IngestResult: ...

@mcp.tool
def corpus_stats() -> CorpusStats: ...
```

### Pydantic schemas (return types)

```python
class DocumentSummary(BaseModel):
    id: str
    source_path: str
    title: str | None
    authors: list[str]
    page_count: int | None
    extraction_method: Literal["unlimited_ocr", "markitdown"]
    chunk_count: int          # derived: count of chunks for this doc
    ingested_at: datetime

class Chunk(BaseModel):
    id: str
    document_id: str
    chunk_index: int
    section_path: str
    heading_text: str | None
    page_start: int | None
    page_end: int | None
    token_count: int
    content: str
    score: float | None = None  # cosine similarity, populated by search()

class IngestResult(BaseModel):
    document_id: str
    source_sha256: str
    page_count: int
    extraction_method: Literal["unlimited_ocr", "markitdown"]
    chunk_count: int
    elapsed_seconds: float
    warnings: list[str]         # e.g., "vLLM unavailable, fell back to markitdown"

class CorpusStats(BaseModel):
    document_count: int
    chunk_count: int
    total_tokens: int
    extraction_method_breakdown: dict[str, int]  # {"unlimited_ocr": N, "markitdown": M}
    embedding_dim: int          # always 1024 for LFM2.5-Embedding-350M
    embedding_model: str        # "LiquidAI/LFM2.5-Embedding-350M"
    last_ingested_at: datetime | None
```

### Resources (4)

- `lean://documents` — JSON list of DocumentSummary
- `lean://documents/{doc_id}/markdown` — full extracted markdown
- `lean://documents/{doc_id}/chunks` — JSON array of chunk metadata (no embeddings)
- `lean://stats` — CorpusStats JSON

### Prompts (3)

```python
@mcp.prompt
def lean_qa(topic: str) -> str:
    """Use the `search` tool to find chunks about {topic}, then answer with citations."""

@mcp.prompt
def lean_glossary(term: str) -> str:
    """Find chunks defining {term} and produce a glossary entry with citations."""

@mcp.prompt
def lean_compare_concepts(a: str, b: str) -> str:
    """Search for both concepts and produce a comparison table with citations."""
```

## 8. Makefile contract (per Quanti-stacks)

```makefile
.PHONY: hooks-install verify db-init db-reset vllm-up vllm-down \
        ingest-all ingest-one search mcp-serve mcp-serve-http api-serve \
        smoke up down

hooks-install:
	pre-commit install --hook-type pre-commit --hook-type pre-push

verify:
	uv run ruff check .
	uv run ruff format --check .
	uv run mypy src tests
	uv run pytest

db-init:
	supabase start
	supabase db reset --file db/schemas

db-reset:
	supabase db reset --file db/schemas

vllm-up:
	docker compose up -d vllm-unlimited
	@echo "Waiting for vLLM healthcheck..."
	@./scripts/smoke-vllm.sh

vllm-down:
	docker compose stop vllm-unlimited

ingest-all:
	uv run python -m lean.cli ingest data/*.pdf

ingest-one:
	@test -n "$(FILE)" || (echo "Usage: make ingest-one FILE=path/to.pdf" && exit 1)
	uv run python -m lean.cli ingest "$(FILE)"

search:
	@test -n "$(QUERY)" || (echo "Usage: make search QUERY='...'" && exit 1)
	uv run python -m lean.cli search "$(QUERY)"

mcp-serve:
	uv run python -m lean.mcp_server

mcp-serve-http:
	uv run python -m lean.mcp_server --transport http --port 8765

api-serve:
	uv run uvicorn lean.api:app --reload --port 8766

smoke:
	./scripts/smoke-vllm.sh
	./scripts/smoke-pgvector.sh

up:
	docker compose up -d

down:
	docker compose down
```

## 9. Decisions log

Each decision with rationale, in chronological order.

| # | Decision | Rationale |
|---|---|---|
| D1 | Standalone repo at `repos/quanti/lean/`, no dep on `web-document-ingestor` | User chose clean boundary; lean/ is its own deliverable. |
| D2 | CLI + FastAPI query service, bootstrapped from `python-llm-service-fastapi` starter | User wants both CLI batch and HTTP query surface. Starter matches Quanti-stacks convention. |
| D3 | PDF extraction: Unlimited-OCR primary via vLLM sidecar, markitdown fallback | Best quality for technical books (tables, formulas, layout). User preference confirmed. |
| D4 | Embeddings: `LiquidAI/LFM2.5-Embedding-350M` (1024-dim, sentence-transformers) | User preference. Beats or matches BAAI/bge-large-en-v1.5 on NanoBEIR & MKQA-11. Drop-in RAG replacement. |
| D5 | Storage: local Supabase via CLI / docker-compose, pgvector | Zero cloud cost, offline-capable, matches Quanti-stacks "containerized local services" rule. |
| D6 | MCP framework: `fastmcp` v3.4.4 standalone | De facto standard (70% of MCP servers), production-grade, Pythonic API. User confirmed. |
| D7 | Chunking: markdown-aware recursive with section-path metadata, 350-450 tokens | Best RAG quality for structured technical books. Preserves semantic boundaries. |
| D8 | HF token via `.env` for both Unlimited-OCR (gated) and LFM2.5-Embedding (trust_remote_code) | Standard practice. Gitignored. |
| D9 | MCP transport: stdio (primary) + HTTP (secondary) | stdio for Claude Desktop / opencode local MCP; HTTP for remote / web clients. |
| D10 | Auth: simple bearer token on HTTP transport (`LEAN_MCP_API_KEY` env var); stdio stays local-trusted | User chose "simple auth". Static token is minimum viable HTTP protection; stdio is impossible to auth (process boundary). Replaces earlier "trusted-local" plan. |
| D11 | lean-app runs as a docker container in the compose stack (not just on host) | User preference: docker-based MCP. Isolates deps, matches Quanti-stacks Docker-first convention. |
| D12 | vLLM runs on remote 3080 Ti (12GB VRAM, SSH-reachable), not on local host | User has a 3080 Ti server. Solves CUDA compat risk (we control its driver) and VRAM (12GB >> 8GB). lean-app talks to it via configurable `VLLM_BASE_URL`. |

## 10. Open decisions (defaults — flag if wrong)

These were not explicitly confirmed but were set as sensible defaults:

- **Corpus scope**: extensible to any PDF, not just the 4 seed books.
- **Asymmetric prompts applied automatically**: rely on `prompt_name` kwarg
  rather than manually prepending `query:` / `document:`.
- **No re-ranking** in v1. LFM2.5-ColBERT-350M documented as upgrade path.
- **No hybrid search** (BM25 + vector) in v1. Pure cosine vector search.
- **No streaming ingestion**. Sync pipeline only.
- **No evaluation harness**. Canonical queries live in `scripts/canonical-queries.json`
  for ad-hoc eval; not automated in CI.

## 11. Out of scope (v1)

- Multi-tenant / auth / RBAC
- Cross-encoder / ColBERT re-ranking
- BM25 hybrid search
- Web UI / Streamlit dashboard
- Cloud deployment, EKS, Supabase cloud
- Streaming ingestion, queue-based async pipeline
- Automated evaluation harness with golden Q&A set
- Multi-modal chunk embeddings (figure/chart understanding)

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|

Document the exact driver/CUDA combo that works in `scripts/setup-3080ti.md`. |
| ~~8 GB VRAM OOM~~ — **resolved by D12**: 3080 Ti has 12 GB VRAM; vLLM uses ~6 GB, leaving comfortable margin. LFM-Embedding runs on lean-app host (no GPU needed for 350M params). | Low | — | Monitor VRAM via `nvidia-smi` on the 3080 Ti during first ingest. |
| 3080 Ti unreachable when lean-app starts (network glitch, SSH tunnel down, host off) | Medium | OCR pipeline falls back to markitdown | `lean.extraction.pipeline` catches `OCRBackendUnavailable`, records `extraction_method='markitdown'` on the document, logs warning. Operator can `reingest` later when 3080 Ti is back. |
| `trust_remote_code=True` for both HF models | Low (both audited OSS) | Supply chain | Pin exact commit hashes in pyproject.toml; document code review in NOTICE |
| vLLM cold start 30-60s on 3080 Ti | High | First ingest delayed | lean-app retries with backoff; `make vllm-health` checks remote `/health` before ingest |
| Unlimited-OCR output not valid markdown (custom output format) | Medium | Chunker fails | Validate output is markdown; if not, run through `mistune` parser to normalize, log warning |
| LFM Open License v1.0 commercial-use clauses | Low (this is personal use) — user confirmed OK | Blocks downstream commercial use | Document clearly in README + NOTICE per user's "fine with licenses" |
| `supabase start` conflicts with other local Postgres on port 5432 | Low | Stack won't start | Use Supabase default port 54322; document in README |
| Long-running ingest blocks MCP server event loop | Medium | Server appears hung | All heavy work runs in `asyncio.to_thread` or `anyio.to_thread.run_sync` |
| Bearer token leaked (e.g., committed to git, logged) | Medium | Unauthorized HTTP access to MCP | `.env` gitignored; token never logged; document rotation procedure in README |

## 13. Testing strategy

- **Unit tests** per module (one `test_*.py` per source module).
- **vLLM mock**: `httpx.MockTransport` returning canned Unlimited-OCR responses.
- **Supabase fixture**: real local Supabase started in pytest session fixture
  (requires `supabase start` before `pytest`); skip with `pytest.mark.integration`
  when Supabase is unavailable.
- **Embedding fixture**: small deterministic text → known vector (regression
  check that the model is loaded correctly).
- **E2E test**: `test_e2e_ingest.py` ingests a tiny test PDF, verifies chunks
  land in pgvector, runs `search`, asserts results. Marked `@pytest.mark.e2e`
  and skipped in CI unless `RUN_E2E=1`.
- **Canonical queries**: `scripts/canonical-queries.json` has 5 Lean Six Sigma
  queries with expected-section substrings. Not automated in CI (manual eval).

## 14. CI policy

GitHub Actions workflow `.github/workflows/ci.yml`:
- Python 3.12, `uv sync --all-groups`, `make verify`
- No GPU in CI → all tests that need vLLM or local Supabase are skipped
  via markers (`@pytest.mark.integration`, `@pytest.mark.e2e`)
- CI runs: unit tests, ruff, mypy, pre-commit hooks
- No deployment, no release automation in v1

## 15. Glossary

- **DMAIC** — Define, Measure, Analyze, Improve, Control. The Six Sigma project methodology.
- **LFM** — Liquid Foundation Model. Liquid AI's model family.
- **MCP** — Model Context Protocol. Anthropic's standard for LLM↔tool interaction.
- **pgvector** — Postgres extension for vector storage and similarity search.
- **Section path** — Hierarchical location of a chunk in the document, e.g. "Chapter 3 > DMAIC > Measure > Data Collection".
- **Sidecar** — A companion service running alongside the main app in the same docker-compose stack.
- **Supabase** — Open-source Firebase alternative built on Postgres. Local CLI mirrors the cloud product.
